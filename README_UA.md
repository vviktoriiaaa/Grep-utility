# mygrep — графічна утиліта пошуку на Rust

## Запуск для користувача Windows 10/11 x64

Відкрийте папку dist та двічі клацніть mygrep.exe. Docker, Rust, Python, браузер і сервер для роботи готової програми не потрібні. Наявність OpenGL 2.0+ та працездатного графічного драйвера потрібна для графічного інтерфейсу. Для повністю відключених або застарілих драйверів рендеринг не гарантується.

Розпакуйте весь архів перед запуском. Не запускайте програму безпосередньо з ZIP. Джерело не має цифрового підпису; Windows може показати попередження про невідомого видавця. Не потрібно запускати від адміністратора.

1. Натисніть «＋ Файли» або «＋ Папка». Можна додати декілька джерел.
2. Введіть слово чи фразу, наприклад «помилка».
3. За потреби змініть параметри. За замовчуванням пошук не враховує регістр і охоплює підпапки.
4. Натисніть «Пошук». Ліворуч можна зупинити пошук. Часткові результати зберігаються у вікні.
5. Оберіть назву файла або текст результату: нижче з'являться повний шлях, номер рядка й повний текст. Рядок і шлях можна скопіювати.
6. «Експорт TXT» або «Експорт CSV» зберігають всі показані результати. CSV використовує роздільник «;», UTF-8 з BOM та коректне екранування лапок. Він придатний для імпорту в Excel; це текстовий експорт, не спеціальний захищений табличний формат. При імпорті сторонніх даних у таблиці обирайте текстовий тип стовпців.

## Відкрити код у Visual Studio Code

Рекомендований каталог: G:\Projects\mygrep. Відкрийте VS Code → File → Open Folder → папку mygrep, у якій лежить Cargo.toml. Установіть запропоноване розширення rust-analyzer. CodeLLDB необов'язкове, для налагодження.

Для збирання:

1. Установіть Rust через https://rustup.rs (стандартне середовище stable MSVC для Windows).
2. Через Visual Studio Installer додайте «Розробка класичних програм мовою C++» до Visual Studio 2022 або Build Tools. Потрібні MSVC x64/x86 та Windows SDK.
3. Перезапустіть VS Code, щоб оновився PATH.
4. Відкрийте Terminal → New Terminal і перевірте `rustc --version`, `cargo --version`.
5. Виконайте `cargo run --locked`. Також можна двічі клацнути start_dev.bat.
6. Для готового EXE двічі клацніть build_windows.bat або виконайте `cargo build --release --locked`.

Результат Cargo: target\release\mygrep.exe. Скрипт build_windows.bat додатково копіює його в dist\mygrep.exe. Перший запуск Cargo завантажує залежності та може зайняти декілька хвилин. Готова програма працює без інтернету. Клієнту можна передавати лише dist\mygrep.exe для користування або весь проєкт для редагування.

Ctrl+Shift+B у VS Code запускає збирання release. Terminal → Run Task → Run mygrep запускає програму.

## Підтримані файли

Текстові файли та журнали: txt, log, md, rst.
Код: rs, py, cs, php, js, ts, jsx, tsx, java, c, cpp, h, hpp, go, rb, swift, kt, sh, bat, ps1, sql.
Вебфайли: html, htm, css, scss, xml, svg.
Конфігурації й структуровані дані: json, yaml, yml, toml, ini, cfg, config, env, .env.

У полі розширень допустимі `txt rs *.log`, розділення пробілами, комами чи крапкою з комою. Фільтр працює і для явно обраних файлів. `*` дозволяє будь-яке розширення, але файл має бути текстовим. Можна вказати конкретне ім'я, наприклад Dockerfile. Розширення порівнюються без урахування регістру. Складні маски на кшталт `file?.txt` не підтримуються. PDF, DOCX, зображення та архіви не розбираються.

## Параметри та обмеження

- Звичайний запит — буквальний текст. Для regex увімкніть «Регулярний вираз». `error|warning` — альтернатива; `^TODO` — початок рядка; `\d+` — число. Backreference і look-around бібліотека regex не підтримує.
- «Ціле слово» використовує межі слів Unicode. Для фраз і пунктуації це саме межі regex, а не лінгвістичний аналіз.
- «Рядки, які НЕ відповідають запиту» інвертує результат перевірки кожного рядка.
- Пошук виконується в межах одного рядка. Нумерація починається з 1. Порожній запит заборонений. Пробіли в запиті зберігаються.
- «Авто» визначає UTF-8 і UTF-16 LE/BE з BOM; для решти пробує Windows-1251. Інші старі кодування можуть бути визначені неправильно. UTF-16 без BOM потрібно вибирати вручну.
- Файли з нульовими символами після декодування пропускаються як двійкові. Це евристика, а не універсальний аналіз формату.
- За замовчуванням розмір одного файла обмежено 50 МБ, результати — 100 000 рядків. Обидва ліміти змінюються у вікні. Досягнення ліміту явно позначається в статусі. Великі ліміти збільшують споживання пам'яті: повний текст знайдених рядків зберігається в оперативній пам'яті.
- Лічильник показує кількість знайдених рядків; три входження слова в одному рядку утворюють один результат.
- Пошук у фоновому потоці. Скасування перевіряється між файлами та рядками; поточне системне читання файла завершується перед скасуванням.
- Повторно доданий той самий файл у перехресних джерелах опрацьовується один раз за канонічним шляхом. Символічні посилання не обходяться. Приховані файли не виключаються; фільтр розширень діє для всіх файлів.
- Відсутність доступу, перевищення розміру, помилки кодування показуються у «Попередженнях». У вікні зберігаються перші 500 повідомлень. Файли, відсіяні розширенням, у лічильник попереджень не входять.
- Порядок результатів відповідає обходу файлової системи. Вихідні файли не змінюються; запис виконується лише під час явного експорту.

## Структура та перевірка

- src/lib.rs — пошук, кодування, фільтр файлів, повідомлення фонового потоку, експорт і тести.
- src/main.rs — графічне вікно eframe/egui, діалоги rfd.
- Cargo.toml / Cargo.lock — залежності та їхні зафіксовані версії.
- examples — невеликі файли для перевірки.
- .vscode — рекомендовані розширення й завдання.

`cargo test --no-default-features --locked` перевіряє ядро без графічного інтерфейсу. `cargo check --locked` перевіряє також GUI. `cargo fmt --check` перевіряє форматування.

Спробуйте папку examples і запит «помилка»: у режимі без урахування регістру буде 3 рядки; «error|warning» з увімкненим regex — 4 рядки. «TODO» знайдеться у вкладеній папці. Вимкнення вкладених папок прибере example.rs із пошуку.
